Overview

What is SpringAuthKit?

Reusable auth infrastructure

SpringAuthKit is a library for Spring Boot applications that need a consistent authentication and authorization foundation. Instead of re-implementing the same login, JWT, password, and role logic repeatedly, a project can add the dependency and let the library wire in the common pieces.

Purpose

The repository is focused on making a Spring Boot app easier to secure with a small set of configuration properties, default beans, and auto-configured services. It depends on Spring Security, JWT, and JPA, and it exposes the authentication endpoints under /auth.

Why SpringAuthKit

Why add it to a Spring Boot project?

🧩

Less boilerplate

The project wires up user services, token services, JWT parsing, and a security filter chain behind a small configuration surface.

🔐

JWT-first

Access tokens and refresh tokens are issued and validated by the library using the secret configured under spring.authkit.jwt.secret.

🧱

Spring Boot integration

The library registers auto-configurations and JPA repositories under the main package, so users typically only add the dependency and properties.

🪪

Role and permission model

Users can have roles and permissions. The principal carries role names and permission names as Spring Security authorities.

📧

OTP and verification

Email verification and password-reset flows are implemented as first-class repository features, with OTP issuance and verification logic.

🛡️

Production-oriented wiring

The code demonstrates stateless security, bean overrides, rate limiting, token rotation, and account lockout, but still expects the app to provide production secret and email infrastructure.

Capabilities

Implemented features in the current codebase

🔑

JWT authentication

Access and refresh tokens are generated, parsed, and used in bearer-authenticated requests.

📋

Registration and login

Users can register with email, username, or phone and receive login tokens after successful authentication.

🔒

Password hashing

PasswordEncoder defaults to BCrypt via BCryptPasswordEncoder, and validation enforces configured password policy.

♻️

Refresh tokens

Tokens are stored as SHA-256 hashes and rotated on refresh; revoked or replaced tokens are rejected.

📧

Email verification

New users can be created in PENDING_VERIFICATION and activated only after OTP verification.

🔁

OTP flows

OTP issuance, verification, resend, and rate limiting are implemented for verification and password reset.

🗂️

Roles and permissions

Role names are configured and assigned to users; permissions can be attached to roles.

⏱️

Rate limiting

OTP and login attempts are limited with RateLimiter, backed by an in-memory implementation by default.

⚙️

Auto-configuration

Spring Boot auto-configurations register the security chain, JPA repositories, services, and default beans.

Installation

Add SpringAuthKit to a Spring Boot application

XML
<dependency>
    <groupId>io.github.devang559</groupId>
    <artifactId>spring-authkit</artifactId>
    <version>1.0.0</version>
</dependency>

What happens after you add it

  • AuthKitAutoConfiguration and AuthKitSecurityAutoConfiguration are imported by Spring Boot.
  • JPA repositories and entity scanning are enabled under io.github.devang559.authkit.
  • Beans like PasswordEncoder, JwtService, TokenService, controllers, and the JWT filter are created if missing.
  • The default security chain protects all endpoints by default except the configured public auth endpoints.

Required application-level setup

  • A relational database such as PostgreSQL or H2 for testing.
  • A strong JWT secret under spring.authkit.jwt.secret.
  • An EmailService implementation if real email delivery is needed.
  • Application properties under the spring.authkit prefix.

Java
import io.github.devang559.authkit.user.AuthKitUser;
import org.springframework.security.core.annotation.AuthenticationPrincipal;
import org.springframework.web.bind.annotation.*;

import java.util.Map;

@RestController
@RequestMapping("/api")
public class NoteController {
    @GetMapping("/notes")
    public Map<String, Object> notes(@AuthenticationPrincipal AuthKitUser principal) {
        return Map.of(
            "user", principal.getId(),
            "identifier", principal.getUsername(),
            "roles", principal.getRoleNames(),
            "authorities", principal.getAuthorities().stream().map(Object::toString).toList()
        );
    }
}

Authentication

Authentication flow

Request flow

  1. A request arrives and passes through the default Spring Security chain.
  2. AuthKitJwtAuthenticationFilter checks the Authorization: Bearer ... header.
  3. The user ID is extracted from the token and the user record is looked up.
  4. AuthKitUser is created and placed into the Spring Security context if the token is valid.

Login and registration

  • Registration validates required fields, password policy, and uniqueness checks.
  • Passwords are encoded with BCrypt by default.
  • Users receive a default role and are set to PENDING_VERIFICATION when email verification is enabled.
  • Successful login issues access and refresh tokens and returns the token pair.
JWT

JSON Web Tokens

Access token

Access tokens are signed with a secret key returned from the configured JWT secret. They include the subject as the user ID, a JWT ID, issuer, issued-at timestamp, expiration, and the claims type, roles, and permissions.

Refresh token

Refresh tokens similarly carry the subject, issuer, and type = refresh, but they are stored hashed in the database and rotated when used. A revoked or replaced refresh token is rejected by the service.

JSON
{
  "sub": "3a8c1d7d-6b6d-48a0-bf2d-12d97925f0f7",
  "iss": "spring-authkit",
  "iat": 1712345678,
  "exp": 1712346278,
  "type": "access",
  "roles": ["USER", "ADMIN"],
  "permissions": ["read:notes"]
}
Users

Users and user fields

AuthUser is the main JPA entity, persisted to the auth_users table. It stores the identifier fields, password, account status, email/phone verification flags, lockout metadata, created/updated timestamps, and the roles assigned to the user.

PENDING_VERIFICATION ACTIVE LOCKED DISABLED
  • Fields enabled by configuration include username, email, phone, first name, last name, display name, and avatar.
  • AuthKitUser is the Spring Security principal and exposes role names and permissions as authorities.
  • Account checks include isLockedNow() and lockout state from failed login attempts.
Roles & Permissions

Roles and permissions

Roles

AuthRole is an entity persisted in auth_roles with a unique name. Role names are configured through spring.authkit.roles.allowed and a default role is assigned by RoleService.assignDefaultRole().

Permissions

AuthPermission is stored in auth_permissions. Permissions can be attached to roles with auth_role_permissions, and they are added to the user’s granted authorities when permissions are enabled.

OTP

Email verification and OTP flows

OtpService issues OTPs with a configured generator and stores them in the auth_otps table. OTPs are hashed before storage, and their purpose is one of EMAIL_VERIFICATION or PASSWORD_RESET.

  • Default OTP generation is performed by SecureRandomOtpGenerator.
  • OTP lifecycle includes send, resend, verify, expiration, and rate limiting.
  • Email delivery is handled by EmailService; the default implementation logs delivery and is meant to be overridden.
Password Reset

Reset flow

When a user requests a reset, the library checks whether an email exists and, if it does, sends a password-reset OTP. The reset request contains the email, the token, and the new password. The password is validated against the configured policy and then hashed before saving.

  • otp — OTP records and purpose handling.
Database

JPA entities and persistence

The library persists a small set of domain entities using JPA:

  • AuthUser in auth_users
  • AuthRole in auth_roles
  • AuthPermission in auth_permissions
  • RefreshToken in auth_refresh_tokens
  • Otp in auth_otps
  • AuditLog in audit_logs if the audit package is used

Relationships include AuthUser to many roles, AuthRole to many permissions, and RefreshToken to a single user. The refresh-token hash is stored for rotation and revocation checks.

Customization

Override points

Default beans

The auto-configuration uses @ConditionalOnMissingBean for the main extension points, making it possible to replace default services without removing the library’s security setup.

  • PasswordEncoder — replace BCrypt with another encoder.
  • EmailService — integrate production email delivery.
  • RateLimiter — swap in Redis, Caffeine, or another implementation.
  • OtpGenerator — customize OTP generation policy.
  • SecurityFilterChain — provide your own chain if you need different rules.

Example

Java
@Configuration
public class MailConfig {
    @Bean
    EmailService authKitEmailService(JavaMailSender mailSender) {
        return (to, otp) -> {
            SimpleMailMessage msg = new SimpleMailMessage();
            msg.setTo(to);
            msg.setSubject("Your verification code");
            msg.setText("Code: " + otp);
            mailSender.send(msg);
        };
    }
}
Production considerations

What SpringAuthKit provides vs. what the application must supply

SpringAuthKit provides

  • Security filter chain, JWT parsing, and authentication filter registration.
  • Login, OTP, email verification, password reset, and refresh-token logic.
  • Default bean wiring and property-based runtime configuration.
  • BCrypt password hashing and stateless token validation.

The app should configure

  • Strong JWT secret management, ideally via environment variables or a secret manager.
  • Relational database credentials and migrations or DDL management.
  • Email provider integration for real delivery and notification traffic.
  • HTTPS and deployment-time security settings.
  • Monitoring, logs, and environment-specific configuration.
FAQ

Common questions

What is SpringAuthKit?
It is a reusable Spring Boot authentication/security library that auto-configures user, JWT, role, OTP, and token services for applications that need a common auth foundation.
Does it require Spring Security?
Yes. The project includes spring-boot-starter-security and configures a stateless filter chain and JWT authentication filter.
Does it use JWT?
Yes. JWTs are issued for access and refresh tokens, and the filter resolves the principal from bearer tokens using the configured secret and issuer.
Does it require a database?
Yes. The library persists users, roles, permissions, OTP records, and refresh tokens through Spring Data JPA entities and repositories.
Can I customize the PasswordEncoder?
Yes. A bean of type PasswordEncoder can be overridden; otherwise the default is a BCrypt encoder.
Can I replace the email service?
Yes. The auto-configuration registers a default EmailService, but any missing bean of that type can be overridden with your own implementation.
How does auto-configuration work?
The library registers AuthKitAutoConfiguration and AuthKitSecurityAutoConfiguration as Spring Boot auto-configurations. These classes enable JPA scanning, configuration properties, security components, and default services when the application has the library on the classpath and spring.authkit.enabled=true.
How are roles handled?
Roles are persisted as AuthRole entities, and a configured default role is assigned at registration. The principal receives role authorities like ROLE_USER.
How are permissions handled?
Permissions are persisted separately and attached to roles. When enabled, they are added to the authenticated principal as granted authorities.
How do I configure JWT expiration?
Use spring.authkit.jwt.access-token-expiration and spring.authkit.jwt.refresh-token-expiration. The default access-expiration is 15 minutes and the default refresh-expiration is 7 days.
How do I disable SpringAuthKit?
Set spring.authkit.enabled=false. Spring Boot will not apply the library’s auto-configurations when that property is disabled.
How do I override a default bean?
Create your own bean of the same type in the application context. The library config uses @ConditionalOnMissingBean, so your bean wins if it is present.
